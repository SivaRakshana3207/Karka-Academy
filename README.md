# Karka AI & Tech Academy — Competition-Ready Flask Website

A polished full-stack Python/Flask concept website for **Karka AI & Tech Academy**, designed around the brief: modern responsive high-performance UX, Karka's vibrant visual language, career tracks, Pay After Placement, placement stories, real internship/project positioning, and a Gen-Z-focused admissions journey.

## Why this build maps to the brief

- **Modern + responsive:** mobile-first CSS, fluid typography, responsive grids, reduced-motion support.
- **Vibrant brand language:** warm paper background + deep plum + orange + yellow + playful geometric UI.
- **Career tracks:** interactive category filtering for Fullstack, Gen AI, Data & ML, Design and Internship.
- **Pay After Placement:** a dedicated journey section with program-term wording.
- **Placement proof:** learner-story carousel using public Karka course-site testimonials.
- **Real project / internship positioning:** Project Studio section designed around real-time internship/client-deliverable messaging; art blocks are intentionally swappable with approved Karka screenshots.
- **Gen-Z conversion:** direct, visual copy; short actions; AI Career Concierge; low-friction admissions form.
- **Full-stack Python:** Flask routes + SQLite lead storage + optional Groq AI endpoint.
- **No frontend build step:** plain Jinja templates + CSS + vanilla JS for fast setup.

## Verified content notes

The copy is based on information published on Karka's public academy pages, including:

- zero upfront / Pay After Placement positioning;
- AI-first curriculum;
- live internship and real client-project positioning;
- onsite mentorship and placement support;
- career-track families across Fullstack, Gen AI, Data & ML, Design, Digital Media, Content & Marketing, Other Tech and Non-Tech;
- a public learner success story featuring Gabriel Samraj as a Frontend Developer;
- course pages that describe 1-on-1 mentoring, resume/portfolio building and mock interviews.

The brief asked for “real internship projects”. Because a final production site should use approved actual project screenshots and links, the demo includes four visually rich placeholders rather than inventing project names or claims.

## Run locally (Windows / VS Code)

### 1. Open the folder

Open `karka-academy-ai` in VS Code.

### 2. Create a virtual environment

```powershell
python -m venv .venv
.venv\Scripts\activate
```

### 3. Install packages

```powershell
pip install -r requirements.txt
```

### 4. Create `.env`

Copy `.env.example` to `.env`.

For the AI assistant, add a Groq key:

```env
GROQ_API_KEY=your_groq_api_key_here
GROQ_MODEL=llama-3.3-70b-versatile
```

The app still works without a key; the assistant falls back to a demo message.

### 5. Start the app

```powershell
python app.py
```

Open: `http://127.0.0.1:5000`

## Deploy to Vercel

The Flask entry point is `app.py`. Vercel detects Flask from `requirements.txt`; `vercel.json` runs `build.py` to copy source assets from `static/` into Vercel's `public/static/` directory and bundles the Jinja templates with the function.

1. Push this repository to GitHub and import it into Vercel, or install the Vercel CLI and run `vercel` from the project root.
2. Add `SECRET_KEY` in Vercel Project Settings. Add `GROQ_API_KEY` only if the AI assistant should use Groq; `GROQ_MODEL` is optional.
3. Deploy. Vercel serves `public/static/` as CDN assets and routes the Flask app through its Python Function.

The app falls back to SQLite at `/tmp/karka.db` on Vercel because the deployed application filesystem is read-only. `/tmp` is temporary and instance-local, so admissions and quiz records are **not durable** across function restarts or instances. Before collecting real applicants, connect a managed persistent database. Do not use the temporary SQLite fallback as a production lead store.

## Main routes

- `/` — main website
- `/apply` — admissions/enquiry form
- `/success` — form success page
- `/api/assistant` — Groq-powered assistant endpoint
- `/api/lead` — JSON lead-capture endpoint

## Database

SQLite creates a local `karka.db` automatically. The `leads` table stores:

- name
- phone
- email
- selected track
- goal
- created timestamp

For production, replace SQLite with a managed database and add authentication, rate limiting, validation, audit logging and a real CRM/email integration.

## Production checklist

1. Add official logo/brand assets supplied by Karka.
2. Replace the four Project Studio art blocks with approved project screenshots + real case-study URLs.
3. Add the academy's current official placement logos and verified student placement records.
4. Replace the demo privacy note with the final privacy/consent text.
5. Set a strong `SECRET_KEY` and `FLASK_DEBUG=0`.
6. Add HTTPS, secure headers, CSRF protection for non-API forms, rate limiting and server-side validation before public deployment.
7. Move lead storage to a managed database and connect the admissions workflow to CRM/WhatsApp/email.

## AI implementation note

The app uses the official Groq Python client when `GROQ_API_KEY` is available. The selected default model in this demo is `llama-3.3-70b-versatile`; you can change it with `GROQ_MODEL`.

The prompt is intentionally constrained to verified Karka facts so the assistant avoids inventing job guarantees, salary figures, partners, fees or student outcomes.

## Design direction

The interface uses the supplied Karka logo, a bright white canvas, plum typography, and restrained violet gradients. Course cards and the Pay After Placement calculator are responsive; motion respects reduced-motion preferences. The frontend remains plain Jinja, CSS, and JavaScript with no separate asset build step for local development.
